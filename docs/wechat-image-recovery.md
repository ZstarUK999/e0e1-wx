# 微信控件定位与游戏重开

微信首次启动、顶号恢复和白屏／黑屏／持续无响应恢复共用控件启动链路，已不再使用图片模板识别入口。抖音仍使用独立的图片导航；微信白屏／黑屏判断仍会截图。

## 定位方式

- 微信原生导航：`wechat_native_controls.js` 通过 Frida 只读微信主进程的 Qt 控件树，读取控件名称、实时矩形和父子关系。由窗口客户区尺寸换算 DPI 后，使用正常鼠标输入点击唯一目标。点击前重新检查前台窗口、位置、尺寸和遮挡。
- 当前原生布局仅验证微信 **4.1.15.55 x64**。校验模块路径、大小和 MainWindow 元数据；其他版本停止定位，不套用旧偏移。已经打开最近使用页面时可直接使用文本入口，无需原生探测。
- 最近使用：`wechat_recent.ps1` 通过 UI Automation 找到“小程序”文档中“最近使用”下的唯一普通版“遗弃之地”。排除“我的常用／我的小程序”以及开发版、体验版。同名候选不唯一时停止。
- Frida 探测运行在独立辅助进程中，最多等待25秒；超时或取消时结束辅助进程。每次探测在 finally 中 detach，不替换小游戏 WeChatAppEx 的已有 Frida 会话。辅助进程通过临时 JSON 文件返回结果，兼容 windowed 打包程序。

## 位置缓存与失败回退

首次扫描后，位置持久保存到用户配置目录的 `wechat_launch_positions.json`。缓存不含 Qt 对象地址；原生控件保存相对客户区位置及微信进程身份，网页游戏入口额外保存 UIA RuntimeId。窗口平移后重算坐标；进程、尺寸、DPI 或控件身份变化时拒绝旧位置并重新扫描。

首次启动与游戏重开共用同一逻辑：优先验证和使用缓存位置，同时启动一个后台只读扫描更新位置。后台扫描不激活窗口、不点击，启动成功无需等待扫描结束。扫描任务只保留一个，插件退出时取消并回收子进程。

缓存点击后最多等待15秒确认游戏窗口。若没有打开，先确认游戏没有延迟出现，再等待位置更新完成、重新定位并使用新位置重试一次。初次点击已打开游戏但回执丢失时不重复点击；两次尝试均失败则结束本轮。缓存文件损坏或写入失败不影响正常扫描。

## 触发条件

- 顶号：沿用顶号设置和等待时间，只处理游戏原生账号重复登录事件。
- 白屏／黑屏：游戏客户区持续纯色至少15秒，且连续确认3次。
- 持续无响应：对已有游戏上下文的独立轻量探测持续失败60秒，且至少确认3次。一次成功会清空确认计时；截图失败不会阻断此分支。
- 用户关闭自动恢复、退出插件、已确认顶号时不运行该恢复分支。每轮结束冷却5分钟。单次任务弹窗失败不会直接被视为游戏无响应。

## 流程

1. 预检查并导航到最近使用页面，验证唯一游戏入口；失败时保留当前游戏窗口。
2. 只向唯一的目标游戏窗口发送普通关闭消息，等待最多15秒；未关闭则停止，不杀微信进程。
3. 调用原有 prepare_reopen，先准备小游戏 Frida 调试监听。
4. 重新确认最近使用入口，并检查是否已有游戏窗口，防止重复打开。
5. 优先按缓存位置点击游戏入口；未确认打开时，使用新扫描位置重试一次，每次点击前重新检查游戏窗口。
6. 由原有连接流程确认大厅并挂载功能。
7. 挂载后处理开屏活动队列：抖音0.1.73的活动模块确认使用 `StitchSoulFirstFaceUI`，仅点击绑定到页面 `close` 的按钮。等待队列清空和大厅稳定2秒才交给功能初始化；陌生页面或未核实按钮停下等待人工处理。

断线截图写入 `logs/recovery/blank_white.png` 或 `blank_black.png`，每种仅保留最近一张。
控件点击要求微信窗口可置前，目标未被其他窗口遮挡。窗口移动、尺寸变化、候选不唯一或版本不匹配时停止并记录阶段。白屏／黑屏截图检查沿用原有可见窗口限制。

重启前在助手内存中标记正在运行的日常自动化、三尸合成和手动狗粮自动合成。只有确认已重新打开游戏，且新会话已关闭开屏页、完成功能初始化、旧任务已收尾后，才消费一次标记从头启动。日常处理器和调度时间重置，合成重新读取库存，不重放结果未知的命令。狗粮已包含在日常托管时不另外重复启动。用户点击停止会取消相应恢复标记；助手进程退出后不保留标记。

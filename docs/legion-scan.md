# 阴司区段扫描

入口：阴司透视 → 区段扫描。输入阴司名称或ID，点击“搜索并创建区段”。

初始边界取种子阴司管理成员玩家ID的最小值与最大值，不按十万区间取整，也没有12399999这样的固定上界。查询阴司成员或点击“刷新数据”时，根据已发现玩家及其阴司的已知成员校准扩大范围。旧任务移除固定区间留下的空白边界，保留已完成范围、玩家数据和并发成功回执，随后按发现的数据继续扩展。

扫描不输出逐批查询、自动恢复等普通日志，只记录异常日志；进度在页面查看。

玩家新增最后在线时间和在线状态，旧数据留空，不主动补查。时间按北京时间显示绝对时间提示，列表显示“刚刚 / x分钟前 / x小时前 / x天前”，无有效时间显示“未更新”。这里使用好友接口的最后在线时间，并非精确登录时刻。

右键阴司 → “立即更新已发现成员信息”会插入一个持久更新队列。当前在途查询正常落库后，优先更新该阴司所有已发现成员，不受自动更新战力门槛或当天已更新限制；完成后继续原扫描断点。失败成员保留重试，异常停止保护仍然有效。

查询并发数可设置1–10，默认2。扫描间隔表示每批自动查询结束后的等待时间。后台独立调度，日常任务忙碌时仍可执行公开查询；游戏完成授权、配置后才开始，断线时保留断点。

并发结果逐个核对玩家ID，成功回执立即保存。某个ID失败时，已成功的其他ID不会重复查询，连续断点只推进至第一个未确认的位置。服务器错误原文显示在状态栏，并记录日志。连续3批错误，或最近20次查询累计5次错误，会停止自动查询；停止原因保存在本地，重启也不会解除，点击“恢复异常停止”手动继续。查无此人不计为错误。

- 从公开预览的三名阎君/判官取得8位玩家ID，先依次查询最小至最大ID，再向大ID查询100个、向小ID查询100个，交替补扫当前范围；一侧到边界后继续另一侧。初始总量取决于种子ID跨度，校准后按实际范围更新总量。旧任务保留已完成边界，从尚未查询的范围继续。
- 扫描间隔默认为1秒，可设置0.1–3600秒，自动保存；表示每次自动查询完成后的最小等待时间，主循环繁忙时实际间隔可能更长。接口报错时至少等待15秒，日志包含操作、目标ID、任务进度和异常堆栈。明确的“未找到对方数据（330015）”视为查无此人并推进进度。
- 每个阴司对应一个持久任务。重复创建会继续原断点；不同阴司可创建多个任务，按创建顺序扫描。可选择区段暂停或继续。
- 每次查询确认成功（包含明确查无此人）后才推进断点。限流、网络错误、登录失效不推进断点，15秒后重试。断线后丢弃旧会话回执。
- SQLite文件 `legion_scan.sqlite3` 位于配置文件旁，微信与抖音数据隔离。记录玩家ID、名称、战力、所属阴司ID和名称、区服、更新时间，以及任务范围、已扫边界和当前位置。
- 自动更新条件为“已标记或战力达标”，满足任一条件即可。启动后先更新符合条件的阴司信息，再更新这些阴司当天未查询的已知成员，最后继续区段扫描。默认门槛3亿，可修改并保存；已标记阴司不受战力门槛限制。新发现阴司首次查询用于获取总战力和发现边界，不等于持续自动更新。
- 根节点显示已发现玩家的最小–最大区服序号，以及总战力最高的阴司名称。展开区段时阴司按最新公开总战力降序排列。右键阴司可标记/取消每日成员更新。
- 玩家按战力降序，每次加载500人，双击“加载更多”继续加载。浏览已展开的树时不会自动重建界面，使用“刷新数据”查看最新扫描结果。
- 战力按万、亿显示，悬停可查看原始数值，排序仍按原始数值进行。

公开阴司预览可能只返回管理成员，成员树展示的是扫描及公开预览已发现的玩家，不保证完整名册。更新标记阴司时会重新获取公开预览，但不会将未返回的成员误判为离会；查询玩家时再更新实际归属。

抖音使用静态脚本和本地通道执行相同查询；升级后需重新进入游戏加载新桥接脚本。

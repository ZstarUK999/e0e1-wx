# 拍卖助手（开发版）

发行版隐藏此面板、不初始化助手、拒绝调用接口，也不包含 auction_runtime.js。

进入游戏「阴司 → 拍卖行」后，GUI读取本地列表，显示拍品、一口价、开拍倒计时和状态。用户多选拍品并点击开始才会执行购买，不持久化自动启动任务。

开拍前500ms起，每100ms调用AuctionService.getAuctionList，直到拿到非空真实列表。此后固定该列表，不再发起列表查询。开拍前游戏生成的1000000起临时ID仅用于预览，绝不提交购买。同一配置的多件拍品以数量/序号对应真实拍品，匹配真实ID后不再变动。

每件选定拍品调用AuctionService.finalPrice({id,cfgId})，最多3次，间隔50ms。返回成功或错误文本含“竞拍已结束”/“拍卖已结束”就停止该件剩余请求；所有拍品完成后停止。没有3秒超时。计时器受游戏帧调度影响，50ms/100ms为目标间隔。

离开拍卖行、切换角色/阴司、手动停止、GUI心跳中断超过5秒或退出插件会停止后续请求；已发送请求无法撤回。早期空列表继续查询，不使用虚构ID。购买消耗游戏实际一口价货币，面板展示配置价格。

测试：node tools/test_auction.cjs；python -m pytest tools/test_auction.py。均为模拟测试，不会购买真实拍品。

诊断日志：游戏事件含实例traceId、递增seq、本地毫秒与服务器时间；列表查询含序号、耗时、数量、错误与是否丢弃迟到回执；购买含真实ID/cfgId、尝试序号、实发次数、距开拍时间、错误码与提示；完成/停止记录最终状态。游戏控制台通过[plugin.ui]即时落盘，GUI状态通道再按traceId/seq去重保存事件作为备份。默认源码日志位于用户配置目录logs/plugin_manager.log，按既有5MB轮转。

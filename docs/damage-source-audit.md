# 伤害报告配置与用词核对

核对基线：抖音缓存包 `tt310e47b3ae06acc002/0.1.71`，以及对应的客户端技能效果实现。只读取客户端数据，未触发游戏操作。

## 2026-10-26：记录与分析分离

- 安装采集器必定启用 `recordOnly`。游戏中只复制真实伤害事件、原生命中乘区、扣血前后状态、属性来源及逐秒分数/属性；不做伤害分类、分桶、来源反查、乘区拆解、分数复算或图表计算，也不再导入额外模拟所需的公式模块。
- `damageCurveJson(cursor)` 返回 `recordingSchema=1` 记录包。配置首次传递，后续按双方事件/命中偏移增量读取。读取不清空游戏缓冲，重试可重放；最后一个分数采样点会重传，以保留快进或结束时的原生修正。采集器重载、复位和战斗切换会使旧游标失效。
- Python 的 `damage_report/analysis.py` 在后台线程中合并记录，分类并统计伤害、曲线和来源，拆解实际乘区并复算分数。HTML 由软件生成，其交互图表在本地报告查看器运行，不进入游戏上下文。
- 新 JSON 保存原始记录和该版本配置，可脱离游戏重新生成 HTML/CSV；旧 JSON 仍按原格式兼容读取。游戏控制台的文本分析、来源汇总、CSV 提示改为在软件中生成。
- 每秒原生分数和属性快照保留；额外调用 `calcDmgRate` 的假想技能快照停止。乘区曲线只展示实际命中证据，未命中时不补造倍率。原始事件每侧最多 30000 条，命中输入最多 12000 条；达到上限保留截断标记，记录模式下报告明确提示曲线仅覆盖已保存事件。
- 离线核对了该缓存配置的 6636 个技能分类与 1975 个 Buff 配置来源，Python 与原 JS 分析器无差异。另以相同原生命中输入核对分类、统计、乘区和分数复算，并用原生好友切磋同步快进验证双方完整记录与结束分数。上述结果不能替代真实运行环境的负载实测。

## 已确认并修复

- Fighter.equipSkills 是技能 ID → 等级；GDRoleSnap.equipSkill 才是槽位 → 天书 ID。两种结构分别读取。
- SkillCfg.bookId 是配置归属，不代表技能属于天书。天书伤害汇总只计天书类技能，普攻、符咒、鬼仆、法器独立保留。
- 水幡有三个技能的枚举类型为天书，但 SeasonWarRestraintCfg 明确引用为战旗技能，按配置来源归类。
- PLAYER_BUFF 在客户端内部创建角色普攻上下文。该关联技能不能用作 Buff 的授予来源。现在分别显示配置来源和关联技能；共享 Buff 标注候选来源，解析不到则保留未知。
- Buff 402083：DesireCfg 6060726 → SkillCfg 402083 → PassiveSkillCfg 402083 → PLAYER_BUFF(402083)。道具名为痴尸舍利，每次释放天书增加 2.25% PVP 增伤，最多八层。
- 元素枚举：土=3，风=4；属性 ID 顺序却是火、水、风、土。符咒及法爆来源拆分改为显式映射，不再直接加枚举值。
- 属性1004为齐射弹射转伤，不是普攻增伤子项，归普通增伤相关属性。
- 三尸常驻汇总读取 DesireCfg.attr，不再用描述提取百分比叠加。技能条件、概率、层数单独注明。
- 天书对比默认折叠，摘要展示主阶等级，展开显示其他分支。仅在双方同书同分支等级可比较时使用红高绿低，缺失及同级保留原色。

## 扫描范围和边界

已遍历251张配置表，并运行实际分类器检查6636个技能、1975个Buff。装备名称及引用覆盖122条脸谱、41条傀儡装、4条法器、39条法器宝石、12条淬炼技能、27条套装技能和488条三尸配置。

配置反查沿 Skill→Passive/Active→Emitter→Bullet→Buff，以及明确的常量授予、概率、条件和连锁引用。不会执行配置表达式。目前1696个Buff能沿这些链找到技能配置；其余279个保留未解析，涉及动态参数、特殊效果处理或没有静态技能引用等情况，不能据此认定没有效果。

另有16个水龙技能引用的110700天书配置在此缓存中不存在；保留原ID，不按相邻ID猜名称。nonBookSkillLinks 是合法的非天书技能配置关联列表，用于检查是否误纳入天书汇总，不代表所有关联均为错误。

审计工具：`node tools/audit_damage_sources.cjs <已解码配置JSON> [审计结果JSON]`。游戏配置不复制到工程。工具离线运行分类器，输出完整扫描与待解析清单。缓存基线不能证明服务端、其他版本的配置完全相同。

已有归档JSON保留原始记录；重新生成HTML可应用界面修改，新的采集才能带上授予链与修正后的分组。涉及战斗结算的倍率仍使用客户端实际采集值。

# 血月功能复核与修复（2026-10-17）

## 比对结论与证据范围

微信反编译包 `wx6d5e82c174635a48/65` 与本机抖音缓存包 `tt310e47b3ae06acc002/0.1.71` 的核心血月加速、挑战、队列资格逻辑一致；不能据此声称整个包、服务端和活动配置完全相同。按虚拟模块名选出的 198 个相关模块中，174 个经格式和函数局部绑定规范化后 AST 相同，24 个不同。关键差异为抖音隐藏队列中的服务器名、分块编号及宿主 Promise 引用。完整源身份、定位方式和局限见 [静态比对报告](bloodmoon-audit/comparison-findings.md)；原包 SHA256 和每模块 UTF-16 偏移见 [module-comparison.json](bloodmoon-audit/module-comparison.json)。

本次使用 REA 技能保留静态解析证据，同时直接分析两个包的选中模块；没有触发真实游戏加速或挑战。REA 仅解析六个提取快照，不能代替完整程序行为证明。

## 已修复的实际问题

1. **慢回执误报成功**：原脚本只观察一秒，却未核实 `settled`。现在只接受唯一匹配请求完成且 ServiceManager 明确返回 `err:null`；超时、网络异常、重复匹配或格式异常均为 uncertain 并锁住后续动作。
2. **无关请求冒充当前回执**：原来取观察窗口内首个请求。现在严格匹配 `SeasonService.moveSpeedUp` / `startPVPBattle` 的函数对象和本次 warId / targetId；仍通过正常 UI 点击，没有自行拼发协议。
3. **行军计数被 ETA 更新清零**：移除 `arrive` 身份键，也不依赖未经现场验证稳定的 start/from。按战场、己方和目的地保守记账，只有观察到结束行军或目的地改变才重置。若两个同目的地的新行军之间未观察到非行军状态，会共用预算而少加速；这比错误清零超额消耗更可控。活动现场需用日志验证实际同步。
4. **道具读取失败仍允许加速**：改用原 UI 所用的 `shopHelper.getItemCount`，读取异常或道具不足不点击；消耗动作必须有服务器时钟和有效时间配置。
5. **只在 Python 检查次数**：点击前 JS 同时核实 max_times、剩余时间、安全余量、冷却、当前行军和道具；弹确认框后再检查一次。
6. **虚拟列表可能点错人**：点击前核对真实按钮 `cbTarget.role.id`、showAttack、原 UI canAttack、当前节点、双方资格和战力阈值。检查等待结束后的按钮状态，不只依赖行序号。
7. **传输丢回执后下一轮重发**：Python 在动作调用抛异常或回执缺少 `confirmed:true` 时保留停止状态；只读读取失败允许恢复，消耗动作不会自动重试。
8. **未知战力当不限**：己方或目标有效战力非正数时不选敌；取整阈值为零不视为不限。点击前再按最新战力、比例和绝对阈值复核。
9. **错误确认进入战斗、场间等待计时偏早**：只有明确状态 3 才确认已进入战斗；缺失、行军或阵亡状态不会解除待确认挑战。观察战斗结束回到待命后才开始 wait_seconds；60 秒未观察到进入战斗则停止，避免再次发起。
10. **复位可能与动作并发或远程失败仍清本地状态**：复位共用操作锁，只在远程明确成功后清本地状态；JS 有请求在途时拒绝复位。开关开合与 stop 不清除不确定状态或在途挑战。
11. **战力上限错误复用任务优先级的 100 万限制**：血月单独允许 JavaScript 安全整数范围，表单用零小数位输入并保存 int，支持实际千万/亿级战力。
12. **界面遗漏**：每阴司摘要人数使用实际 top_members；轮询 ready 不再错误启用正在运行的探测启动按钮；未证实来源的 ext[4] 标注改称“隐匿中”，不假定全部来自水旗。

共享修改仅涉及血月调度、血月脚本及其表单/配置部分；微信 Frida、CDP、连接、授权与其他游戏脚本未修改。修复同时用于两平台的同一套血月脚本。

## 日志：分支依据和错误路径

Python INFO 日志记录插件分支所读取的配置、快照与动作结果，不依赖默认关闭的 DEBUG。相同决策依据每 30 秒补一次心跳；变量变化立即记录。每个动作的 JS trace 随回执一起落文件，包含调用序号、步骤、时间、异常堆栈。原始游戏内部不可访问的服务器变量无法由客户端日志补齐。

- `血月决策 poll/speed/attack/marks`：总开关及各子配置、安装/关闭/注入/探测状态、轮询到期、停止原因、待确认挑战、已观察战斗、上次动作时刻、次数、同步超时。
- `march_snapshot` 与 `speed.context/preflight/clickGuard`：warId、己方状态、起终点、start/arrive、服务器时间、剩余时间、冷却截止、UI 禁用原因、配置原值、道具 ID/需求/持有量、加速次数与上限、安全余量、行军预算键。
- `candidate_snapshot`、`target_threshold/target_<id>/target_selected` 与 `attack.clickGuard`：己方战力、计划战力、比例、绝对阈值、计算阈值；各候选 ID、战力、资格和原因；绑定行的真实角色、按钮 showAttack、官方资格检查、预期/实际节点及 warId。
- `button.preflight/click/waitTimeout`：节点/按钮是否存在、名称、emit 是否可用、active、interactable、enabled、continuous、clickInteractable 和等待时长。
- `rpc.sent/ignored/settled/exception/observed`：准确方法、匹配参数、忽略无关请求的原因、匹配数量、是否 settled、原始 ServiceManager 回执、服务端错误码、异常与停止原因。
- flags、诊断、标注启停、复位记录原始返回值；模块导入、状态读取、列表等待和清理异常记录步骤与堆栈。标注定时器错误保留在 diagnose 中，启用标注时 Python 每 30 秒读取并落盘。

日志沿用管理器实际配置路径旁的 `logs/plugin_manager.log`；本机源码运行路径已核实为 `%LOCALAPPDATA%/e0e1/e0e1-wx-plugins/logs/`，自定义配置或打包运行路径不同。现有轮转为每份 5 MiB、保留三份历史；出问题后请一并保留 `.log`、`.log.1`、`.log.2`、`.log.3`，避免后续轮询覆盖问题时段。日志不写桥接 token 或账号口令，但会包含排障所需角色与战场信息。

1. 更新后重启管理器，并退出小游戏重新进入，使当前上下文使用 `script_version=2026-10-17-audit`。先只打开血月诊断/战旗探测，保存日志，确认 warId、己方、地图、服务器时钟及加速配置真实下发。

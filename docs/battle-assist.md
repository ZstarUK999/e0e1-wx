# 对战辅助：控制链

GUI 根节点「PVE辅助 → 控制链」。总开关、逐本开关和次数立即保存；次数包含第一次手动释放。面板可滚动。

当前配置全部16本天书均有入口：铜钱鬼剑、断佛手、玄水瓶、风沙琵琶、火焰山、青女、石敢当、业火幡、雷公、风煞阵、遣将阵、霜轮阵、万尸瀑、傩戏铃、黄天令，以及单独悬浮控制的十绝阵。配置中没有110700天书，不虚构缺失名称或技能。

次数选择「自动（按本场等级）」时，以本场实际攻击冷却除以主效果时长向上取整；指定1～20则保留玩家指定的总次数。旧配置的开关、次数保持原值，新加天书默认关闭。瞬发无持续效果时，自动次数为1，需要多放时指定数字。

启用后，首次成功手动释放启动该本辅助，记住战斗坐标；再次成功手动释放停止该本辅助（本次手动施法仍正常执行）。辅助自身释放不会切换开关。达到数量后停止补放；本场结束后清空记录。

调度采用 `n + min(l, m/数量) + m*k`：n 为上一本实际释放的战斗时间，l 为效果时长，m 为本场技能对应的攻击冷却。选择卡牌冷却允许的最早周期；到点能量不足等情况顺延到下一周期，不集中补放。例如傩戏铃20秒周期、8秒效果、数量3，间隔为20/3秒；风煞12秒周期、4秒效果、数量3，间隔为4秒。m 与卡牌释放冷却不同；卡牌就绪条件始终通过游戏自身 `canUseSpecialCard` 检查。每次释放仍走原有 `useSkill`，正常扣能量、记录操作、检查次数和位置。

每场从 `BattleData.leftTeam.team[].skillLevel/epicAwakening` 读取参战等级与觉醒，使用官方 `getEvolutionSkillId` 验证实际施法技能。沿实际根技能的 `sumSkill` 读取攻击冷却，不将觉醒技能在基础列表之外的情况视为不支持，也不以账号主页等级替代本场等级。

主效果规则：玄水瓶、傩戏铃读取周期攻击的间隔与次数；万尸瀑读取尸毒时长；黄天令读取主场地寿命；遣将阵追踪第二层召唤与登场攻击创建的结界。霜轮阵、青女读取实际冰冻Buff基础时长；断佛手读取眩晕时长。铜钱鬼剑读取持续燃烧，火焰山读取灼烧，没有持续效果的低阶版本按攻击冷却衔接。风煞阵读取主控制Buff的4秒时长，低阶没有该控制时长时回退攻击冷却；额外觉醒Buff不替代主控制时长。石敢当读取主眩晕2／4秒；雷公有主减速时读取3秒，低阶无减速时回退攻击冷却。风沙琵琶、业火幡以攻击冷却作为效果时长。这五本均不记忆落点；是否有落点与时间调度分别处理。

当前有觉醒替换技能的六本为十绝阵、风煞阵、遣将阵、霜轮阵、万尸瀑、黄天令，共62个替换根技能（包含四相、五行分支）。其余10本在当前配置中没有觉醒替换根技能。测试覆盖128个基础阶数及62个觉醒替换，共190个配置变体。

这是按实际技能配置计算的简化相位策略，不是逐敌人Buff追踪。冰冻时长还会受控制增强与目标抗性影响，飞行命中及技能执行时间也会影响覆盖。采用底层基础时长，不把描述文字当计时依据，不保证所有目标无缝。无法解析的未来变体保留失败原因，不能沿技能链确定时长时不会猜值施放。能量不足、次数上限仍可能导致断档。

十绝阵单独配置「显示十绝阵悬浮开关」。每场游戏内开关默认关闭，点击开启后，在正常施法条件满足时持续释放，控制链到期施法优先。浮窗可拖动；跨战斗、关闭总开关或停用插件都会清空开关。

仅接入有本地 `SystemCardLogic` 的正常战斗；回放、实时帧同步、服务端结算 PvP 不接管。微信和抖音使用同一运行时，打包脚本包含该文件。

离线验证：`node tools/test_battle_assist.cjs`；PowerShell 设置 `$env:BATTLE_ASSIST_CASE='catalog'` 后运行同一脚本可遍历全部190个配置变体；`python -m pytest tools/test_battle_assist_gui.py` 校验完整清单、旧配置兼容、自动次数和导航。真实游戏覆盖仍需实测，测试不会启动对战或消耗游戏资源。

每本可设置施法间隔（0为自动，手动范围0.01～3600秒，精度0.01秒）。手动值替代自动相位偏移，仍遵守冷却与能量限制，必要时顺延攻击周期。旧配置缺省为自动；修改间隔会在下一战斗帧重算活动链的下一次时间。

间隔输入项是公式中的偏移 l；自动输入框内直接显示“释放间隔x秒”，保留完整计算值，不另加说明行。手动输入框同样使用“释放间隔x秒”格式。复位只恢复该本 l 为自动。未读取本场数据时先显示8阶基础技能的默认参考间隔（悬停说明来源），进入对战后按本场等级和觉醒覆盖；离开后恢复默认参考，不沿用上一场数值。

触发控制链后，游戏浮窗按天书逐行显示进度、下一次施法倒计时，以及游戏自身能量检查、卡牌冷却和次数上限的状态。再次手动释放停止、完成或关闭链后显示5秒现实时间倒计时，再隐藏该行；不改变能量不足时顺延攻击周期的调度。未开启十绝阵浮窗时，控制链状态也独立显示。


## PVE辅助 → 钟馗伏魔

桌面新增「钟馗伏魔」子模块。默认显示5个最低存活波次的怪物，可设1至20个；逐个显示名字、血量及血条，列表直接排入同一个主辅助面板。再次点击当前二级菜单可折叠内容。波次通过stageConfig.phase中的位置映射，不将CompMonster.phase配置ID直接加1；未匹配时不猜波数。暂停或原生弹窗打开时隐藏辅助面板和箭头。死亡记录保留2秒现实时间，再由同一最低波次的候选补位，不把更高波次混入列表。超过屏幕容量可翻页。位置由战斗相机投影到UI空间，以蓝箭头和白色外描边及编号对应怪物。

游戏内浮窗仅允许PvE，回放及所有PvP不接入。标题可拖动，点击收起为圆球，圆球标注「点击展开」并有呼吸圈，展开/收起带缩放反馈。展开后分「控制链」「钟馗伏魔」二级菜单，十绝阵独立按钮与控制链进度仍可使用。收起时隐藏怪物列表及箭头，后台控制链继续。

钟馗伏魔默认勾选提前启用3倍加速图标（模块本身默认关闭）。它只提前开放按钮，不自动切换速度，玩家可点原生图标或浮窗3倍按钮。原生UISubdueBattle.isSpeedUpVisible以类型11、HyakkiUnlockSpeedUp[0]及usedSpecialCardNum控制；已解码配置为[15,3]。本实现仅对当前钟馗世界返回可见和[0,3]，退出/禁用时恢复原方法，不改天书次数上限，也不改全局配置。

源码通信核查：ui-subdue-battle.ts的onClickSpeedUp调用setSpeed；ui-battle-base.ts的setSpeed只更新battleTime.timeScale/baseTimeScale及按钮外观；system-player-action-logger.ts未记录倍速开关。hyakki-module.ts的endBattle发送battleId、battleType、stageId、win、dropItems、wave、static、verifyData、battleTime、killMonster、input、inputGzip，没有倍速开关字段。高级钟馗的onPhaseMaxWave仍调用updateProgress发送battleId、battleType、waveId、stageId；没有屏蔽或改写。结论仅为当前本地源码路径未直接上报「倍速开关/数值」，不能据此断言服务器无法通过时间、施法和校验数据验证战斗。此结论未通过抓包证明所有平台/后续版本的所有遥测。

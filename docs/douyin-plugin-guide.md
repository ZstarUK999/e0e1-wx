# 微信 / 抖音平台选择

直接启动 `python plugin_main.py`，先选择“微信小游戏”或“抖音 PC 小游戏”，再建立连接。选择前不会启动微信调试引擎，也不会修改抖音游戏缓存。关闭并重开管理器即可重新选择。

也可用 `python plugin_main.py --platform wechat` 或 `--platform douyin` 跳过选择器。现有嵌入调用 `main(config_path)` 保持微信默认；若要选择器，使用无参数入口，或直接创建 `PluginApplication(..., platform=None)`。

## 微信

保持原 Frida/WMPF/CDP 连接与功能面板，不改变既有账号授权流程。

## 抖音 PC

1. 选择“抖音 PC 小游戏”。如果还没有游戏缓存，先打开一次《遗弃之地》。
2. 管理器会检测固定 appid `tt310e47b3ae06acc002` 的缓存版本，备份根 game.js，然后安装本地桥接代码。界面会提示退出并重新进入小游戏。
3. 退出小游戏后重进大厅；管理器通过实际心跳和大厅状态确认连接，再挂载原来的驻留脚本。伤害分析等面板通过同一套功能脚本工作。
4. 进入战斗后，伤害面板可按原有方式取数、生成报告；跨版本业务行为仍应先验证再开启自动化。

抖音使用平台 FileSystemManager 与本地命令文件通信，不开放 HTTP/WebSocket 调试端口。命令验证随机凭据、运行会话、递增序号和请求标识；超时后不重发，等待原回执或确认上下文已重建。记录的是请求结果，不把超时当作操作取消。

抖音沙箱限制了 eval 与 Function。管理器把原驻留代码和功能脚本作为静态函数一同编入缓存入口，运行时只发送带参数的命令（如安装、启用伤害采集、取状态），不接受 JS 字符串执行。原脚本正文和原启停包装仍复用。修改脚本或桥接代码后，需先重启管理器，再重进小游戏，才能加载新的静态代码。

源码调试版会跳过正式版授权门禁，原来的玩家 ID 查询也位于该门禁内。抖音现在通过心跳只读当前角色的 ROLE.id（缺失时回退 heroId），独立更新状态栏与玩家面板的 ID 显示；断线或角色 ID 缺失时清空。显示不会修改授权结果，也不会触发后台账号上报。微信分支及正式版授权校验维持原流程。

游戏入口更新会自动重新适配同一 appid 下的版本目录。入口结构无法匹配、已装补丁或备份哈希不符时会停止写入并显示原因；不会猜偏移或覆盖未知改动。缓存安装是持久修改，退出管理器不会自动移除入口桥接。小游戏上下文重建时只有确实重新执行了该入口，桥接才会重新装载。

备份与校验清单位于插件配置目录的 `douyin-bridge/`；通道文件位于该游戏 `user/` 目录，均以 `e0e1-plugin-` 开头。请勿在运行中删除备份或凭据。

如需恢复磁盘入口，先关闭小游戏，在项目虚拟环境中运行：

```python
from package.plugin_manager.douyin import DouyinCache
from package.plugin_manager.paths import default_config_path
cache = DouyinCache(default_config_path().parent)
cache.restore()
```

恢复只接受与本管理器清单匹配的补丁和原文件备份；不会覆盖其他修改。恢复后需重进小游戏才能移除当前运行时的桥接代码。
